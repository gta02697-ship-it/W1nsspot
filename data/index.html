О ПРОЕКТЕ // W1NSSPOT

Текущий статус системы

А зачем?

Вообще изначально это было для друзей без интернета, и зайти на сайт могли только те, кто знали как. Эта сеть не была в открытом доступе.

Но сейчас, когда знакомые начали узнавать о «ГДЗ без интернета» или «такой же бесплатной нейросети», все начали приставать: «Дай покажи, мне интересно». Поэтому вот теперь всё в открытом доступе.

Работает без интернета

Да, это правда. Портал не использует глобальную сеть. Весь контент (чат, файлы, картинки) хранится и обрабатывается локально. Вы подключены к Wi-Fi точке, но данные никуда не уходят. Это полностью автономный узел.

Архитектура узла

Связка из двух плат: M5StickC Plus2 раздает Wi-Fi и делает редирект, а ESP32 DevKit с SD-картой отдает сайт, файлы и принимает сообщения. Все данные хранятся в оперативной памяти и на SD-карте.

Техническая документация

АРХИТЕКТУРА УЗЛА

Узел построен на базе ESP32-WROOM (M5StickC Plus2). Файловая система: LittleFS (смонтирована как read-only). Веб-сервер: синхронный WebServer (порт 80).

Сетевой стек: LwIP (TCP/IP). Точка доступа: WIFI_AP (канал 1, 12 клиентов max).

ПРОТОКОЛ ВЗАИМОДЕЙСТВИЯ

1. Клиент отправляет HTTP GET / на 192.168.4.2:80.

2. Сервер читает /index.html из LittleFS, упаковывает в чанки (Chunked Transfer Encoding) и отправляет клиенту.

3. Для API используется HTTP POST с телом application/x-www-form-urlencoded.

ПЛАНЫ РАСШИРЕНИЯ

1. SPI-Мастер: Подключение SD-карты через VSPI (CS=5, SCK=18, MISO=19, MOSI=23) на второй плате (DevKit).

2. Синхронизация времени: NTP-клиент для работы расписания ИИ (если будет интернет).

3. Техническая пауза: Чтение GPIO 36 (кнопка) и отправка WebSocket-сигнала всем клиентам для активации видео-оверлея.

СИСТЕМНЫЕ КОМАНДЫ

(Для отладки через Serial)

AT+RST — перезагрузка узла.

AT+FS_INFO — информация о LittleFS.

AT+WIFI_LIST — список подключенных клиентов.
